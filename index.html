Vue.js

The Progressive JavaScript Framework

What is Vue.js?

  • A UI framework for building interactive web interfaces.
  • Builds on top of standard HTML, CSS & JavaScript — no magic.
  • Declarative: describe what the UI should look like, Vue handles DOM updates.
  • Component-based: build small reusable pieces and compose them into larger apps.
  • Progressive: use as a simple script tag OR a full SPA framework — your choice.

Template Syntax

How Vue connects your data to the DOM

Text Interpolation & Expressions


<script setup>
import { ref } from 'vue'
const name  = ref('World')
const count = ref(5)
</script>

<template>
  <!-- Text interpolation -->
  <h1>Hello, {{ name }}!</h1>

  <!-- JavaScript expressions inside {{ }} -->
  <p>{{ count * 2 }}</p>
  <p>{{ name.toUpperCase() }}</p>
  <p>{{ count > 3 ? 'Big' : 'Small' }}</p>
</template>
⚠️ Only single expressions work inside {{ }} — no statements like if or for.

Attribute Binding: v-bind


<script setup>
const imageUrl  = ref('logo.png')

const isDisabled = ref(true)
</script>

<template>
  <!-- Full syntax -->
  <img v-bind:src="imageUrl">

  <!-- Shorthand : (used in practice) -->
  <img :src="imageUrl" :alt="'Logo'">

  <!-- Dynamic class and disabled state -->
  <button :class="btnClass" :disabled="isDisabled">
    Click me
  </button>

  <!-- Object syntax for multiple classes -->
  <div :class="{ active: isActive, 'text-bold': isBold }"></div>
</template>

Core Directives

Special attributes that control rendering & behavior

Event Handling: v-on


<script setup>
const count = ref(0)
function increment() { count.value++ }
</script>

<template>
  <!-- Full syntax -->
  <button v-on:click="increment">+</button>

  <!-- Shorthand @ (used in practice) -->
  <button @click="increment">+</button>
  <button @click="count--">-</button>

  <!-- Event modifiers -->
  <form @submit.prevent="handleSubmit">...</form>
  <div @click.stop="doThis">...</div>

  <!-- Key modifiers -->
  <input @keyup.enter="search">

  <p>Count: {{ count }}</p>
</template>

Two-way Binding: v-model


<script setup>
const username = ref('')
const agreed   = ref(false)
const role     = ref('user')
</script>

<template>
  <!-- Text input -->
  <input v-model="username" placeholder="Enter name">
  <p>Hello, {{ username }}</p>

  <!-- Checkbox -->
  <input type="checkbox" v-model="agreed"> I agree

  <!-- Select dropdown -->
  <select v-model="role">
    <option value="user">User</option>
    <option value="admin">Admin</option>
  </select>
</template>
v-model is syntactic sugar for :value="x" + @input="x = $event".

Conditional: v-if vs v-show


<script setup>
const isLoggedIn = ref(false)
const hasError   = ref(true)
</script>

<template>
  <!-- v-if: element is REMOVED from the DOM -->
  <h1 v-if="isLoggedIn">Welcome back!</h1>
  <p v-else-if="hasError">Something went wrong</p>
  <p v-else>Please log in</p>

  <!-- v-show: stays in DOM, toggles display:none -->
  <div v-show="isLoggedIn">User menu</div>
</template>

v-if — Use when condition rarely changes. Higher toggle cost.

v-show — Use for frequent toggles. Always rendered in DOM.

List Rendering: v-for


<script setup>
const fruits = ref(['Apple', 'Banana', 'Cherry'])
const users  = ref([
  { id: 1, name: 'Alice', role: 'Admin' },
  { id: 2, name: 'Bob',   role: 'User' },
])
</script>

<template>
  <!-- Simple array -->
  <li v-for="fruit in fruits" :key="fruit">{{ fruit }}</li>

  <!-- Array of objects -->
  <div v-for="user in users" :key="user.id">
    {{ user.name }} — {{ user.role }}
  </div>

  <!-- With index -->
  <p v-for="(fruit, i) in fruits" :key="i">
    {{ i + 1 }}. {{ fruit }}
  </p>
</template>
⚠️ Always provide a unique :key — it helps Vue efficiently update the DOM.
Vue.js

Reactivity System

ref() & reactive()

ref() — Universal Reactive Value


import { ref } from 'vue'

// Works with any type
const count = ref(0)
const name  = ref('Alice')
const items = ref([])
const user  = ref({ name: 'Bob', age: 25 })

// In <script>: must use .value
count.value++
name.value = 'Charlie'
items.value.push('new item')
user.value.age = 26

// In <template>: .value is auto-unwrapped
// {{ count }}   ✅ Vue handles it for you
💡 Modern Vue best practice: use ref() for everything — it's consistent and predictable.

reactive() — Object Reactivity


import { reactive } from 'vue'

const user = reactive({
  name: 'Alice',
  age:  30,
  address: { city: 'Mumbai' }
})

// No .value needed — direct property access
user.name = 'Bob'
user.age++
user.address.city = 'Delhi'

✅ Good for: grouped form fields or complex objects with many related properties.

⚠️ Gotcha: Destructuring loses reactivity.

// ❌ name is no longer reactive
const { name } = user
Vue.js

Computed & Watchers

Computed Properties


import { ref, computed } from 'vue'

const firstName = ref('John')
const lastName  = ref('Doe')
const price     = ref(100)
const quantity  = ref(3)

// Derived state — cached until dependencies change
const fullName    = computed(() => `${firstName.value} ${lastName.value}`)
const total       = computed(() => price.value * quantity.value)
const isExpensive = computed(() => price.value > 500)

// Writable computed
const fullNameWritable = computed({
  get: () => `${firstName.value} ${lastName.value}`,
  set: (val) => {
    [firstName.value, lastName.value] = val.split(' ')
  }
})
Computed values are cached — they only re-run when their reactive dependencies change. Methods run on every render.

watch()


import { ref, watch } from 'vue'
const query   = ref('')
const results = ref([])

// Watch a single ref
watch(query, async (newVal, oldVal) => {
  results.value = await searchAPI(newVal)
})

// Options
watch(query, handler, {
  immediate: true,  // also run on component mount
  deep: true,       // watch nested object changes
})

// Watch multiple sources at once
const firstName = ref('John')
const lastName  = ref('Doe')
watch([firstName, lastName], ([newFirst, newLast]) => {
  console.log('Name changed:', newFirst, newLast)
})

watchEffect()


import { ref, watchEffect } from 'vue'
const userId = ref(1)

// Automatically tracks ALL reactive deps used inside it
// Runs immediately on mount
watchEffect(async () => {
  const data = await fetchUser(userId.value)
  console.log('User data:', data)
})

watchEffect: Auto-tracks deps. Runs immediately. Great for effects with multiple deps.

watch: Explicit deps. Lazy by default. Gives you old & new values.

Vue.js

Lifecycle Hooks

Hook into key moments of a component's life

Lifecycle Overview

onBeforeMount() Component about to mount. DOM not ready yet.
onMounted() DOM ready. ✅ Fetch data & access DOM refs here.
onBeforeUpdate() Reactive state changed, DOM update pending.
onUpdated() DOM has re-rendered after reactive changes.
onBeforeUnmount() Component about to be destroyed. ✅ Clean up here.
onUnmounted() Component destroyed. Clear timers & event listeners.

Lifecycle in Practice


<script setup>
import { ref, onMounted, onBeforeUnmount } from 'vue'

const data       = ref(null)
const windowWidth = ref(window.innerWidth)
let intervalId   = null

onMounted(async () => {
  // Fetch data when component is ready
  data.value = await fetchUsers()

  // Start a polling interval
  intervalId = setInterval(() => fetchUpdates(), 5000)

  // Listen to browser events
  window.addEventListener('resize', handleResize)
})

onBeforeUnmount(() => {
  // ALWAYS clean up to prevent memory leaks
  clearInterval(intervalId)
  window.removeEventListener('resize', handleResize)
})
</script>

Pass data deep down the component tree without prop drilling.

Vue.js

Composables

Reusable stateful logic — Vue's answer to custom hooks

Creating a Composable


// composables/useFetch.js
import { ref } from 'vue'

export function useFetch(url) {
  const data    = ref(null)
  const error   = ref(null)
  const loading = ref(true)

  fetch(url)
    .then(res => res.json())
    .then(json => { data.value = json; loading.value = false })
    .catch(err => { error.value = err; loading.value = false })

  return { data, error, loading }
}
    

<!-- Use in any component -->
<script setup>
import { useFetch } from '@/composables/useFetch'
const { data: users, loading, error } = useFetch('/api/users')
</script>
<template>
  <div v-if="loading">Loading...</div>
  <div v-else-if="error">Error!</div>
  <ul v-else>
    <li v-for="u in users" :key="u.id">{{ u.name }}</li>
  </ul>
</template>

// Global guard in router/index.js

  const isLoggedIn = !!localStorage.getItem('token')

    next({ path: '/login', query: { redirect: to.fullPath } })
  } else {
    next()
  }
})

// Per-component guard

Pinia

Global State Management

Defining a Store


// stores/auth.js
import { defineStore } from 'pinia'
import { ref, computed } from 'vue'

export const useAuthStore = defineStore('auth', () => {
  // STATE
  const user  = ref(null)
  const token = ref(localStorage.getItem('token'))

  // GETTERS (computed)
  const isLoggedIn = computed(() => !!token.value)
  const fullName   = computed(() => user.value?.name ?? 'Guest')

  // ACTIONS
  async function login(email, password) {
    const res   = await api.post('/login', { email, password })
    token.value = res.data.token
    user.value  = res.data.user
    localStorage.setItem('token', token.value)
  }

  function logout() {
    user.value  = null
    token.value = null
    localStorage.removeItem('token')
  }

  return { user, token, isLoggedIn, fullName, login, logout }
})

Using the Store in Components


<script setup>
import { useAuthStore } from '@/stores/auth'
const auth = useAuthStore()
</script>

<template>
  <div v-if="auth.isLoggedIn">
    <p>Welcome, {{ auth.fullName }}!</p>
    <button @click="auth.logout()">Logout</button>
  </div>
  <div v-else>
    <button @click="auth.login(email, pass)">Login</button>
  </div>
</template>
Pinia stores are accessible from any component. State is shared globally and reactive everywhere.

Nuxt.js

What is Nuxt?

Nuxt = Vue + Framework Layer

  • Full-stack framework built on top of Vue.js.
  • File-based routing — no manual router config needed.
  • Multiple rendering modes — SSR, SSG, SPA, and ISR.
  • Auto-imports — components and composables imported automatically.
  • Built-in server (Nitro) — write API endpoints alongside your UI.
  • SEO-friendly by default — server renders full HTML on first load.

Nuxt.js

Rendering Modes

Choose how and when HTML is generated

4 Rendering Modes Explained

Mode When HTML is generated Best for
SPA In the browser (client) Dashboards, admin panels
SSR On the server per request E-commerce, dynamic content
SSG At build time (static files) Blogs, docs, marketing pages
ISR Build time + periodic re-gen High-traffic sites needing fresh data 

// nuxt.config.ts — set per route with routeRules
routeRules: {
  '/':        { prerender: true },   // SSG — build time
  '/blog/**': { swr: 3600 },         // ISR — rebuild every hour
  '/admin/**':{ ssr: false },         // SPA — no SSR for admin
}

Data Fetching

Isomorphic — works on server AND client

useFetch


<script setup>
// Fetches on SERVER during SSR → no flash of empty content
// Refetches on client during navigation

// With options
const { data: user } = await useFetch('/api/user', {
  method: 'POST',
  body:   { name: 'Alice' },
  headers: { Authorization: 'Bearer ...' },

useAsyncData — More Control


// Use any async logic, not just fetch
const { data: posts } = await useAsyncData(
  'posts',               // unique cache key
  () => $fetch('/api/posts')
)

// Combining multiple requests in one call
const { data } = await useAsyncData('dashboard', async () => {
  const [users, orders] = await Promise.all([
    $fetch('/api/users'),
    $fetch('/api/orders')
  ])
  return { users, orders }
})

useFetch: Simple URL-based fetching. Cache key auto-generated from URL.

useAsyncData: Custom async functions, named cache keys, parallel requests.

Server API with Nitro

Full-stack in one project

Creating API Endpoints


// server/api/users.get.ts   → GET /api/users
export default defineEventHandler(async (event) => {
  const users = await db.user.findMany()
  return users
})

// server/api/users.post.ts  → POST /api/users
export default defineEventHandler(async (event) => {
  const body = await readBody(event)
  const user = await db.user.create({ data: body })
  return user
})

// server/api/users/[id].get.ts  → GET /api/users/42
export default defineEventHandler(async (event) => {
  const id   = getRouterParam(event, 'id')
  const user = await db.user.findUnique({ where: { id } })
  if (!user) throw createError({ statusCode: 404 })
  return user
})
File naming: name.METHOD.ts — Nitro auto-registers the HTTP method.

Consuming Your Own API


<!-- pages/users/index.vue -->

</script>
During SSR, Nuxt calls the server handler directly in memory — no HTTP round trip. During client-side navigation it becomes a real HTTP fetch.

Vue vs Nuxt — Summary

Feature Vue SPA Nuxt
Routing Manual (Vue Router) ✓ File-based (auto)
SEO ✗ Poor (client render) ✓ Excellent (SSR/SSG)
Data Fetching onMounted + fetch ✓ useFetch / useAsyncData
Auto-imports ✗ All manual ✓ Fully automatic
Backend / API ✗ Separate project needed ✓ Built-in (Nitro)
Rendering Modes SPA only ✓ SSR, SSG, SPA, ISR
Layouts Manual setup ✓ Built-in layouts system
Learning Curve Low Medium (worth it!)
